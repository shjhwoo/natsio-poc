읽기'와 '쓰기'의 차이
NATS JetStream 서버의 입장에서 두 연산은 완전히 다릅니다.

CreateConsumer와 DeleteConsumer:

이는 '쓰기(Write)' 연산입니다. 서버의 상태(State)를 변경합니다.

새로운 컨슈머를 위한 리소스를 할당하고, 내부 메타데이터를 업데이트하며, 클러스터에 변경 사항을 동기화해야 합니다. 여러 클라이언트가 동시에 이 작업을 요청하면 서버에 큰 부하가 걸립니다. 이는 마치 도서관에서 책을 빌렸다가 바로 반납하는 행위를 수없이 반복하는 것과 같습니다. 사서(서버)가 엄청난 양의 행정 업무를 처리해야 합니다.

stream.Info():

이는 '읽기(Read)' 연산입니다. 서버의 상태를 변경하지 않습니다.

JetStream은 모든 스트림의 최신 상태(마지막 시퀀스 번호, 메시지 수 등) 정보를 항상 메모리에 최적화된 상태로 가지고 있습니다. Info() 함수는 이 정보를 단순히 조회만 하는, 매우 가볍고 빠른 연산입니다. 이는 도서관의 전자 카탈로그를 조회하는 것과 같습니다. 책의 위치나 상태는 바로 확인할 수 있고, 이 행위는 다른 사람에게 아무런 영향을 주지 않습니다.

결론적으로, stream.Info() 함수는 서버에 부하를 거의 주지 않으므로, 이 함수를 사용해 메시지 수를 조회하는 것은 JetStream의 안정성을 해치지 않는 안전하고 올바른 방식입니다.
